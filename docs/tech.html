무엇을 하는 프로그램인가

윈도우 바탕화면 위에 투명한 창으로 사는 고양이 비서예요. 고양이는 스스로 걷고 쉬고 자고, 정해 둔 시각이 되면 풍선으로 일정·소식·새 메일을 알려 주고, 뒤에서 랜섬웨어 같은 수상한 행동을 지켜봐요. 설치형이라 관리자 권한이 필요 없어요.

고양이

살아 있는 그림

실제 고양이 사진 컷(동작 33가지·컷 331장)을 상황에 맞게 넘겨 가며 보여 줘요. 바닥·창 윗변 위를 걷고, 뛰어오르고, 떨어지고, 바탕화면 아이콘을 차요.

생활

하루 리듬

배고픔·기분, 잠자는 시간(22~07시), 밥 시간 3번, 놀아 달라는 요구. 쓰다듬고 집어 올리고 털색도 바꿀 수 있어요.

런처

반원 앱 런처

고양이를 누르면 머리 위에 반원이 열려요. 캘린더·Gmail과 내가 등록한 프로그램·웹·명령·윈도우 도구를 바로 열어요.

알림

캘린더·소식·메일·어제 한 일

하루 한 번 또는 매시 정각에, 보조 프로세스가 인터넷에서 가져온 내용을 풍선과 창으로 알려 줘요. Gemini는 정리만 해요.

경비

경비 고양이

랜섬웨어(미끼 파일·대량 변경), 새 자동 시작·수상한 프로그램, 카메라·마이크, 다운로드 파일을 지켜보고 알리기만 해요. VirusTotal 조회는 선택이에요.

바탕

지킴이·설정·설치

고양이가 죽으면 살리는 지킴이, 분홍 설정 창, PyInstaller 로 묶은 설치·삭제 프로그램이 있어요.

설계 원칙 다섯 가지

코드의 모든 선택은 아래 다섯 가지로 설명돼요. 다시 만들 때도 이 원칙이 우선이에요.

1. 가볍게

며칠씩 켜 두는 프로그램이에요. 평소 CPU는 코어 1개의 약 1%, 메모리는 약 110MB. 무거운 일(인터넷·서명 확인)은 짧게 살다 사라지는 보조 프로세스에서 해요.

2. 안 죽게

지킴이가 따로 지켜보고(하트비트 90초), 프레임 오류는 한 프레임 단위로 가두고, 자원이 새면 스스로 다시 시작해요.

3. 비밀은 비밀로

API 키·앱 비밀번호·캘린더 주소는 윈도우 계정 암호화(DPAPI)로 저장하고, 명령줄 대신 표준 입력으로만 넘기고, 로그에 남기지 않아요.

4. 알리기만

경비 고양이는 파일을 지우거나 프로그램을 끄거나 막지 않아요. 사용자가 경보 창의 버튼을 직접 누를 때만 조치해요.

5. 고양이 말투

고양이가 하는 말은 ~냥·~옹으로 끝내요. 단, 날씨·뉴스·시세처럼 밖에서 가져온 정보와 경보 문구는 또렷한 존댓말로 써요.

지킴이 감시 상태 — 눌러서 시험해 보기

지킴이는 2초마다 본체를 살펴요. 아래 버튼으로 네 가지 상황을 재생해 보세요(대기 시간 계산이 코드와 같아요).

지킴이 상태 기계
버튼을 눌러 보세요.
HANG_SECONDS   = 90      # 하트비트가 이 시간 없으면 멈춘 것
STARTUP_GRACE  = 90      # 시작 직후 이만큼은 봐 준다
def _watch(proc, hb, started):
    last_poll, grace_until = time.time(), started + STARTUP_GRACE
    while True:
        rc = proc.poll()
        if rc is not None: return rc
        time.sleep(2.0)
        now = time.time()
        if now - last_poll > 20:          # 우리도 같이 잠들었다 깸 = 절전 복귀
            grace_until = now + 60
        last_poll = now
        if now > grace_until and now - hb.last() > HANG_SECONDS:
            proc.kill(); proc.wait(10); return "hang"

def run_guard(extra):
    # 뮤텍스(이미 있으면 return 0) ... hb = Heartbeat(); fast_fails = 0
    while True:
        started = time.time(); hb.beat()
        proc = subprocess.Popen(child_cmd(extra), creationflags=CREATE_NO_WINDOW,
                                stdin=DEVNULL, stdout=DEVNULL, stderr=DEVNULL)
        rc = _watch(proc, hb, started)
        if rc == EXIT_QUIT: return 0                       # 0 = 사용자가 끔
        if rc == EXIT_RESTART:                             # 3 = 스스로 재시작 요청
            fast_fails = 0; continue
        uptime = time.time() - started
        fast_fails = fast_fails + 1 if uptime < 30 else 0
        wait = 3 if fast_fails <= 1 else min(300, 3 * 2 ** min(fast_fails, 7))
        time.sleep(wait)                                   # 계속 죽어도 포기하지 않는다

종료하는 방법과 종료 순서

정상 종료

메뉴 종료 → cleanup() → app.quit() → main() 이 app.exec() 의 값(0)을 돌려줌 → 지킴이가 EXIT_QUIT 로 보고 함께 끝. 바탕화면 아이콘은 icons.shutdown() 이 원래 자리로 돌려놓고 격자 정렬도 되살린다.

스스로 재시작

자원 점검(60초마다)이나 프레임 오류가 계속되면 ask_restart(이유): 로그에 이유를 남기고 cleanup() 후 app.exit(3). 지킴이는 기다리지 않고 곧바로 다시 띄운다.

심장 박동 — 24fps 프레임 루프

고양이의 모든 것은 QTimer 하나가 42ms 마다 부르는 frame() 에서 시작해요. 이 함수 하나가 행동 → 그리기 → 알림 점검 → 건강 점검을 순서대로 하고, 느린 일은 시간 간격으로 걸러서 해요. 평소 CPU 가 코어 1개의 약 1% 인 이유는 대부분의 일을 걸러서 하기 때문이에요.

10초 동안의 일정표 (줄 이름을 누르면 설명)

frame_body() — 실행 순서 그대로

def frame_body():
    now = time.perf_counter(); dt = min(0.1, now - last); last = now; n += 1
    # (1) 건강 신호 — 멈춘 동안에도 계속
    if heartbeat and now >= next_beat: next_beat = now + 5.0; heartbeat.beat()
    if (n % 30 == 0 or paused) and WaitForSingleObject(quit_event, 0) == WAIT_OBJECT_0:
        cleanup(); app.quit(); return
    mono = time.monotonic()
    if mono >= next_check:                       # 60초마다 자원 점검
        next_check = mono + 60
        u = process_usage()
        if u and (u["ws_mb"] > LIMIT_MB or u["handles"] > 5000 or u["gdi"] > 7000 or u["user"] > 7000):
            ask_restart("자원 사용량이 너무 큼"); return
        if not tray.isVisible(): tray.show()
    # (2) 멈출지 판단 (1초마다)
    if not args.no_autopause and now >= next_power:
        next_power = now + 1.0; set_paused(_power_state(overlay.hwnd))
    # (3) 알림 — 멈춘 동안에도 제 시각에 일을 시작한다
    activity.tick(mono)                          # 5초마다 맨 앞 창 표본
    scheduler.tick(mono)                         # 20초마다 시각 점검
    if paused: return                            # ---- 여기부터는 고양이가 보이는 동안만 ----
    # (4) 화면
    keep_cat_on_top(mono)                        # 1초마다
    if mono >= routine_next[0]: routine_next[0] = mono + 2.0; handle_routine(routine.tick(mono))
    if n % 50 == 0: ... 모니터 구성이 바뀌었으면 world.set_areas + brain.relocate()
    brain.update(dt)      # 행동 상태기계 + 물리
    overlay.tick(dt)      # 창 위치 옮기기 + (필요하면) 다시 그리기 요청
    launcher.tick(); balloon.tick()

오류를 가두는 겉옷 frame()

한 프레임에서 오류가 나도 프로그램은 꺼지지 않아요. 세 겹으로 지켜요.

1. 한 프레임 가둠try/except 로 로그만 (10초에 한 번만 기록)
2. 20프레임 연속 오류brain.reset() — 두뇌를 처음 상태로
3. 10분 안에 3번 resetask_restart → 종료 코드 3 → 지킴이가 재시작

멈춤(paused)의 뜻

상태들어가는 조건하는 일나오는 조건
None 평소—타이머 42ms—
"full"제목 표시줄이 없는 앞 창이 고양이가 있는 모니터를 완전히 덮음(게임·동영상). 제목 표시줄이 있는 최대화 창은 해당 안 됨.런처·풍선·소식 창 닫고 고양이 창 숨김, 타이머 500ms앞 창이 바뀜 → 창을 다시 보임
"away"GetLastInputInfo 기준 입력 없음 ≥ 600초창은 그대로 두고 멈춤, 타이머 500ms입력이 생김

멈춘 동안에도 하트비트·종료 이벤트·자원 점검·활동 표본·알림 시각 점검은 계속 돌아요. 이때 끝난 알림 결과는 held 목록에 쌓아 두었다가(최대 12건, 매시 알림은 하나로 합침) 돌아오면 1.5초 뒤에 보여 줘요 — 풍선이 아무도 못 본 채 사라지지 않게요.

고양이 창(Overlay)이 하는 일

창의 성격

플래그 FramelessWindowHint | WindowStaysOnTopHint | Tool | NoDropShadowWindowHint, 속성 WA_TranslucentBackground | WA_ShowWithoutActivating. 만든 뒤 GWL_EXSTYLE 에 WS_EX_NOACTIVATE | TOOLWINDOW | LAYERED 를 더한다. 크기는 W = max(300·s, 260), H = 150·s + 80, 발바닥 기준점 anchor = (W/2, H−18).

클릭 통과

매 틱 마우스가 몸(히트 사각형의 가로 10~90%, 세로 10~100%) 위에 있을 때만 WS_EX_TRANSPARENT 를 끈다. 그 밖에서는 클릭이 아래 창으로 그대로 간다 — 고양이 창이 바탕화면을 가리지 않는 비결.

그리기 횟수 줄이기

그리기가 비싸서(프레임당 ~17ms) 간격을 둔다: 움직일 때 매 틱, 쉬는 자세 0.125초, 잘 때 0.2초마다. 단 자세가 바뀌는 중(photo.busy)에는 매 틱. 타이머가 늦어도 틱을 건너뛰지 않게 −12ms 여유.

마우스

왼쪽 누르고 6px 넘게 끌면 brain.grab()+hold() (0.3초마다 keep_on_top), 놓으면 release()(최근 속도로 던져짐, ±700 한계). 끌지 않고 놓으면 on_click(런처 열기). 오른쪽은 메뉴. 몸 위에서 쓱쓱 움직이면 쓰다듬기(_pet_energy).

프레임 시간 계산 규칙

  • dt = min(0.1, 실제 경과) — 오래 멈췄다 와도 한 번에 0.1초 이상 진행하지 않아요(순간이동 방지).
  • 타이머 종류는 PreciseTimer — 기본(Coarse)은 윈도우 눈금 15.6ms 에 맞춰져 프레임 간격이 24~47ms 로 들쭉날쭉해요.
  • 모든 "몇 초마다"는 time.monotonic()(시계가 바뀌어도 안전), 실제 시각이 필요한 곳(스케줄러·루틴)만 datetime/time.time().

컷 사이 섞기 (blend)

컷이 바뀌는 순간 두 사진을 섞으면 부드럽지만, 자세 차이가 크면 두 자세가 겹쳐 안개 같은 잔상이 생겨요. 그래서 이웃 컷의 실루엣 차이(gap)를 미리 재서(tools/frame_gaps.py → sprites.json 의 gaps) 섞는 길이를 줄여요.

GAP_FULL=0.04 이하 → 최대로 섞음
GAP_ZERO=0.09 이상 → 섞지 않고 선명하게 바꿈
BLEND_SPAN=0.45 컷 사이 시간의 뒤쪽 45%까지만
GAP_FULL, GAP_ZERO, BLEND_SPAN = 0.04, 0.09, 0.45
def _pick(key, idx, wrap):
    total = len(meta[key]["frames"])
    pos = idx * meta[key].get("mult", 1)          # 중간 컷을 만든 동작은 저장된 컷이 mult 배 많다
    i0 = floor(pos); fr = pos - i0
    i0 = i0 % total if wrap else clamp(i0, 0, total-1)
    i1 = (i0 + 1) % total if wrap else min(total-1, i0 + 1)
    if i1 == i0: return i0, i0, 0.0
    gp = gaps[key][i0] if gaps.get(key) and i0 < len(gaps[key]) else 1.0
    w = BLEND_SPAN * clamp((GAP_ZERO - gp) / (GAP_ZERO - GAP_FULL), 0, 1)
    if w <= 0: return i0, i0, 0.0                 # 섞지 않고 선명하게
    k = clamp((fr - (1 - w)) / w, 0, 1)           # 시간의 '뒤쪽 w' 구간에서만 섞는다
    return i0, i1, k*k*(3 - 2*k)                  # smoothstep

  1. 컷 고르기 _select → _pick → _frame(key, i) 로 두 컷의 _Frame 객체(QPixmap + 크기·중심·머리 위치)를 얻어요. 컷은 처음 쓸 때 만들고 캐시해요: PNG 읽기 → (털색이 갈색이 아니면 색 바꾸기) → 눈 다시 그리기 → premultiplied 변환 → 화면 크기(store→scale·dpr)로 축소.
  2. 전환 겹침 동작(사진 폴더)이나 바라보는 방향이 바뀌면 직전 그림을 기억해 두었다가 0.10초(빠른 동작 0.05초) 동안 서서히 사라지게 하고 새 그림을 나타나게 해요. 사라지는 쪽은 (1−fade)² 로 빨리 옅어져 잔상이 오래 남지 않아요.
  3. 좌표 맞추기 발바닥 기준점 origin 으로 이동(물리 픽셀에 맞춰 반올림), 왼쪽을 보면 scale(-1, 1).
  4. 바닥에 걸치기(sink) 발을 바닥에 딱 맞추면 오히려 떠 보여서 SINK=2.5px 아래로 걸쳐 그려요. 누운 자세는 rest(몸 아랫선이 맨 아래보다 몇 줄 위인가)에 0.9 를 곱해 최대 8px 더 내려요. 공중 자세(jump_up jump_down hold hop)는 0. 작업 표시줄이 없는 화면 맨 아래에서는 room−1 로 제한.
  5. 그림자·소품(아래) 타원형 그라데이션 그림자(scale(1, 0.10)), 꾹꾹이 방석, 밥그릇, 안은 털실공.
  6. 고양이 컷 하나 또는 둘(fr 만큼 투명도) → 소품(위) 굴러다니는 털실공.

핵심 아이디어

사진의 털 부분만 골라 밝기(줄무늬·털결)는 그대로 두고 색만 바꿔요. 눈동자·코·귀 안쪽 분홍·혀는 털이 아니라서 색상(hue)으로 걸러져요. 흰 수염·하이라이트는 채도가 낮아 제외.

다음 행동 뽑기 — 눌러서 확률 보기

고양이는 "방금 한 행동"에서 이어질 수 있는 행동만 후보로 삼고(예: 달린 뒤 곧장 눕지 않음), 개연성 × 기본 가중치 × 상황 배수 에 비례해 뽑아요. 아래는 실제 flow.choose 와 같은 계산이에요.

def choose(last, base, allowed, mult=None, rng=random):
    r = FLOW.get(last) or FLOW["start"]          # 방금 행동의 후보표
    cand, wts = [], []
    for k, aff in r.items():
        if k in allowed and k in base and aff > 0:
            wt = base[k] * aff * mult.get(k, 1.0)  # 기본 가중치 × 개연성 × 상황 배수
            if wt > 0: cand.append(k); wts.append(wt)
    if not cand:                                  # 후보가 모두 막히면 얌전한 것 중에서
        cand = [k for k in ("sit", "idle", "sittilt") if k in allowed] or list(allowed)
        wts = [1.0] * len(cand)
    return rng.choices(cand, wts)[0]

def activity_mult(hour):                          # 고양이는 해 뜰 때·질 때 활발, 한낮엔 낮잠
    if 7 <= hour < 10 or 17 <= hour < 21: return 1.35, 0.75   # (이동·놀이 배수, 잠 배수)
    if 11 <= hour < 16:                      return 0.65, 1.35
    return 1.0, 1.0

def _mult(self):                                  # CatBrain
    move, nap = activity_mult(self.hour_fn())
    m = {k: move * (1.4 if happy else 1.0) for k in ("walk","trot","run","sneak","jump","travel","kick","tailplay","knead")}
    m["sleep"] = nap * (1.5 if sad else 0.7 if hungry else 1.0)      # sad = 기분 < 30
    if hungry or sad:
        for k in ("run","kick","tailplay","knead","trot"): m[k] = 0.0

행동마다 길이가 달라서 고르는 확률만으로는 시간 비율이 안 맞아요(잠은 한 번에 40~150초, 하품은 2.4초). 그래서 "개연성 표 + 행동 평균 길이"로 만든 마르코프 연쇄의 정상 분포를 계산해서, 목표 시간 비율(TARGET_DAY)이 나오도록 기본 가중치(WEIGHTS_DAY)를 solve() 가 자동으로 맞춰요. 가중치는 미리 계산해 상수로 넣어 두었고(python tools/test_flow.py --print 로 다시 뽑음), 시작할 때마다 계산하면 2초쯤 걸리기 때문이에요.

시뮬레이션: 낮 동안 목표 비율에 가까운가?
버튼을 누르면 20,000번 연속으로 뽑아서 행동 길이(평균)를 곱한 시간 비율을 목표와 비교해요.
def solve(kinds, target, iters=400):
    w = {k: 1.0 for k in kinds}; tsum = sum(target.values())
    for _ in range(60):
        P = {i: normalize({j: w[j] * row(i).get(j, 0) for j in kinds}) for i in kinds}   # 전이 확률
        pi = stationary(P, iters // 4)                                                    # 정상 분포(반복 곱)
        share = {k: pi[k] * mean_dur(k) for k in kinds}                                   # 시간 비율 = 확률 × 평균 길이
        group = sum_by_group(share, GROUP_OF)                                             # 묶음별 %
        for k in kinds:
            w[k] *= ((target[GROUP_OF[k]] / tsum * 100) / group[GROUP_OF[k]]) ** 0.6      # 모자라면 키우고 넘치면 줄임
    return w

시각 판단 규칙 — 직접 해 보기

Scheduler.due_slot 은 "오늘 이미 지난 시각 중 가장 최근 것이 아직 안 돌았으면 그것"을 돌려줘요. 아래에서 시각·마지막 실행·최대 지연을 바꿔 보세요.

CHECK_EVERY = 20.0                       # 초
def due_slot(self, name, now):
    sch = settings.data["schedules"].get(name, {})
    if not sch.get("enabled"): return None
    last = settings.data["last_run"].get(name, "")
    best = None
    for t in sorted(x for x in sch.get("times", []) if valid_time(x)):
        slot = "%s %s" % (now.date().isoformat(), t)                  # "2026-10-16 09:00"
        if slot <= now.strftime("%Y-%m-%d %H:%M"): best = slot        # 오늘 지난 칸 중 가장 최근
    max_age = sch.get("max_age_min")
    if best and max_age:                                              # 매시 알림: 오래 지난 칸은 따라잡지 않는다
        if (now - strptime(best)).total_seconds() / 60 > max_age: return None
    return best if best and best > last else None                     # 문자열 비교로 충분 (같은 형식)

def tick(self, mono_now, now=None):
    if mono_now < self._next: return
    self._next = mono_now + CHECK_EVERY
    if self.quiet and self.quiet(): return                            # 잠자는 시간: 깬 뒤 가장 최근 하나만 따라잡는다
    for name in self.jobs:
        if name in self._running: continue
        slot = self.due_slot(name, now or datetime.now())
        if slot:
            settings.data["last_run"][name] = slot; settings.save()  # 실행 '전에' 적는다: 실패해도 같은 시각에 되풀이하지 않는다
            self.run(name)

1. 랜섬웨어 — 세 가지 단서

감시 폴더(문서·사진·다운로드; 바탕화면은 제외)마다 숨김 속성의 진짜 .docx 두 개를 둬요: !_고양이미끼_회의록.docx (알파벳 순으로 걷는 랜섬웨어가 가장 먼저 건드림), ~_고양이미끼_견적서.docx (마지막). 만들 때의 SHA-256 을 canary.json 에 저장. 수정·삭제·이름 바꾸기·내용 변경이 감지되면 곧바로 위험(60초 안에 재경보 없음). 속성만 바뀌어 내용이 같으면 무시. 프로그램이 꺼진 동안 건드려졌으면 시작할 때 알려요.

10초 창에서 기존 파일 변경(수정·삭제·이름 바꾸기)이 문턱 이상(보통: 파일 25개 · 폴더 2곳)이고, 다음 중 하나가 같이 나타나면 위험: (가) 낯선 확장자 하나로 한꺼번에 이름이 바뀜(새 확장자가 흔한 목록 밖이고 8개 이상·전체의 60% 이상), (나) 고르게 뽑은 8개 파일의 앞 4KB 가 암호화된 것처럼 보임(원래 머리글이 깨짐 또는 엔트로피 과다)이 60% 이상. 새로 만든 파일의 쓰기(압축 풀기·복사·다운로드)는 센 대상이 아니에요(만든 지 30초 안).

README·DECRYPT·HOW_TO_RECOVER·restore·unlock·ransom·!!help·your_files 계열 이름의 .txt .html .hta .url .rtf .md 가 3개 폴더 이상에 생기면 문턱을 절반으로 낮춰서 보고, 변경이 문턱의 절반 이상이면 경보에 가점.

무시하는 것: 이 프로그램 폴더·데이터 폴더, 폴더 이름이 .git node_modules __pycache__ $recycle.bin .venv site-packages .idea .vscode appdata cache temp build dist target … 인 곳 안, 임시 확장자(.tmp .crdownload .part .swp …), 오피스 잠금 파일(~$…). 그리고 경보 후 120초 쿨다운.

경보는 바로 기록하고(화면이 곧장 알리도록), 별도 스레드가 1.5초 동안 프로세스별 WriteTransferCount 증가량을 두 번 재서 쓰기량(MB/초)이 가장 큰 상위 3개를 "의심 후보(확정 아님)"로 경보에 덧붙여요(events.update).

2만 개 압축 풀기·지우기에도 CPU 가 낮도록 watchdog 대신 ReadDirectoryChangesW 를 직접 써요(64KB 버퍼, 폴더 이름 변화는 안 받음). 버퍼가 넘치면(ERROR_NOTIFY_ENUM_DIR 또는 0바이트) 놓친 사건 속에 미끼가 있었을 수 있어 미끼를 직접 확인해요(1초에 한 번). 사건 목록 상한 30,000개, 판단 때 최근 5,000개만, 판단은 사건 도착 후 0.25초 안.

def looks_corrupt(ext, head):            # 앞 4KB 가 '암호화/깨진 것'처럼 보이는가
    if len(head) < 64: return False
    if ext in MAGIC: return not any(head.startswith(m) for m in MAGIC[ext])   # .docx → PK.., .pdf → %PDF ...
    if ext in (".mp4", ".mov", ".m4a"): return head[4:8] != b"ftyp" and entropy(head) > 7.2
    e = entropy(head)                                                          # 섀넌 엔트로피 0~8 (무작위 ≈ 8)
    if ext in TEXT_EXT: return e > 6.6
    return e > 7.6 and not head.startswith(ANY_MAGIC)

  2. PowerShell 은 무거워서 아끼기: 예약 작업·서비스는 PowerShell(Get-ScheduledTask, Get-CimInstance Win32_Service)로 읽는데 시작 비용이 커요(CPU 약 3초·메모리 100MB). 그래서 레지스트리에서 "지문"(작업의 경로·실행 명령, 서비스의 시작 방식과 자동 시작 서비스의 실행 파일)을 SHA-1 로 만들어 지난번과 같고 6시간 안이면 지난번 결과를 재사용해요(0.2초).
  3. 처음 돌 때는 기준 목록(baseline.json)만 저장하고 알리지 않아요(지금 있는 것은 평소 쓰던 것). 그 뒤 새로 생긴 항목만 알려요. 알린 것도 기준에 넣어요.
  4. 서명 확인(sec_sig.check_many): 새 항목·수상한 위치 프로그램·시스템 이름 프로그램의 경로를 모아 PowerShell Get-AuthenticodeSignature 를 한 번에 최대 60개씩 호출. 결과는 "경로|수정시각|크기" 키로 보관(Error 는 보관 안 함).
  5. 실행 중 프로그램 점수 (아래 계산기). 같은 건은 7일 동안 다시 안 알림(seen.json), 허용 목록이면 안 알림, 고양이 자신의 폴더는 제외.

3. 카메라·마이크 (sec_privacy.py)

  • 윈도우는 사용 기록을 HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\(webcam|microphone)\NonPackaged\(경로의 \ 를 # 으로 바꾼 이름) 또는 ...\(webcam|microphone)\(스토어 앱 이름) 의 LastUsedTimeStart/Stop(FILETIME)에 적어 둬요.   • 처음 보는 프로그램이 쓸 때만 알려요(프로그램당 한 번). 크롬·엣지·줌·팀즈·슬랙·디스코드·카카오톡·OBS 등 널리 쓰는 앱(KNOWN_OK)은 처음부터 믿고, 켠 뒤 처음 24시간은 배우는 기간(알림 없이 기억만). 허용 목록에 넣으면 다시 안 알려요.

4. 내려받은 파일 (sec_download.py)

  • 다운로드 폴더(비재귀)에서 .exe .msi .scr .com .pif .dll, 스크립트(.js .vbs .ps1 .bat .cmd .hta .jar …), .lnk .iso .img .vhd .cab .reg 만. 임시 확장자(.crdownload 등)는 건너뛰고, 이름이 바뀌어(moved) 완성되면 살펴봐요. 크기가 2초 동안 안 변해야 다 받은 것으로 봐요. 0바이트·2GB 초과는 제외.
  • 출처: 파일 끝에 붙는 대체 데이터 스트림 파일:Zone.Identifier 의 ZoneId=3 = 인터넷, HostUrl(출처 주소).

5. VirusTotal (선택, 기본 꺼짐)

  • 키는 설정 탭에서 입력 → DPAPI 로 secrets.json 의 vt_key. 조회는 서명이 유효하지 않은 수상한 파일의 SHA-256 해시만(내용·이름·경로는 안 보냄): GET https://www.virustotal.com/api/v3/files/{sha256} + 헤더 x-apikey, 키는 표준 입력으로만.
  • 무료 한도 지키기(Limiter): 요청 사이 16초(MIN_GAP), 하루 450건(DAILY_MAX), 결과를 해시별로 30일 보관. 한 번의 점검에서 최대 5건.
  • 판정: 악성 판정 엔진 ≥ 3 → 위험으로 올림, 1~2 또는 의심 ≥ 3 → 의심(오탐일 수도 있다고 안내), 0 → 문제 없음(의심이던 것을 참고로 내리고 제목에 "(VirusTotal에서 문제 없음)"), 404 → "정보 없음" (안전하다는 뜻이 아님이라고 반드시 적음).
  • 연결 시험은 모든 백신이 잡는 표준 시험 파일 EICAR 의 해시(275a021b…)로 해요.

진짜 악성코드 금지

랜섬웨어는 "무작위 바이트로 덮어쓰고 이름을 .locked 로 바꾸는 흉내"만. VirusTotal 연결 시험은 표준 시험 파일 EICAR 의 해시로.

가짜 서버

Gemini·VirusTotal·IMAP 은 127.0.0.1 에서만 도는 가짜 서버로 시험(환경 변수로 주소를 바꿀 수 있지만 127.0.0.1 만 허용해서 키가 밖으로 새지 않음).

가짜 시계·입력

Routine(now_fn), Scheduler.tick(now=), ActivityLog(read_fg, read_idle, is_locked, today), scan(collectors, sig_runner, now) 처럼 바깥 세계를 바꿔 끼울 수 있게 설계했어요.

실제 화면에서 확인하기

  • 시험용 데이터 폴더로 실행: DESKTOPCAT_DATA=임시폴더 + DESKTOPCAT_AWAY_FLAG 등으로 상황을 만들고 화면을 캡처해서 풍선·창·쥐 잡기를 눈으로 봐요. 시험이 끝나면 임시 폴더를 지워요.
  • 자원: 설치본·개발본을 켜 두고 CPU·메모리를 재요. 목표: 평소 코어 1개의 약 1%, 메모리 약 110MB, 경비를 켜도 +0.3% / +10MB 이내, 72시간 이상 안 죽기.
  • 이 문서의 숫자·그래프는 코드에서 자동으로 뽑아요: python docs/build_docs.py → docs/assets/gen-data.js.
시험 중에 얻은 교훈 경비 시험 중 내가 만든 가짜 미끼가 다른 실행의 감시를 놀라게 한 적이 있어요 → 멀쩡한 기존 미끼는 새로 덮어쓰지 않고 이어받도록(_adopt) 고쳤어요. 시험이 실제 사용 환경에 번지지 않게 데이터 폴더를 분리하는 것이 중요해요.

덫 — 겪었던 문제와 해결 (꼭 피하세요)

증상원인해결
프레임 간격이 24~47ms 로 들쭉날쭉기본 타이머(Coarse)가 윈도우 눈금 15.6ms 에 맞춰짐setTimerType(PreciseTimer)
걸음이 가끔 뚝뚝 끊김틱과 안 맞는 그리기 간격(격틱), 이모지 글자를 매 프레임 그리면 40~700ms움직일 땐 매 틱, 글자는 미리 그림으로, 타이머 지연 여유 −12ms
며칠 뒤 갑자기 죽음GDI/USER 개체·핸들이 조금씩 샘 (프로세스당 약 10,000개 한계)60초마다 측정, 임계 넘으면 exit(3) 로 스스로 재시작
고양이·말풍선이 겹쳐 보임(이전 프레임이 안 지워짐)그리다 오류가 나서 QPainter.end() 가 안 불림try/finally 로 반드시 end()
창 위에 서 있는데 발이 떠 보임/빠져 보임창의 그림자 여백 포함 사각형을 씀, 컷 맨 아래의 빈 줄DWMWA_EXTENDED_FRAME_BOUNDS, 컷의 빈 줄만큼 내리기, SINK=2.5
가상 데스크톱에서 안 보이는 창 위로 올라섬다른 데스크톱 창도 IsWindowVisible 가 참DWMWA_CLOAKED 확인
작업 표시줄을 누르면 고양이가 뒤로 숨음작업 표시줄도 '항상 위' 창끌 때 0.3초마다, 앞 창이 바뀔 때 1초마다 SetWindowPos(HWND_TOPMOST …) (단 시작 메뉴 같은 윈도우 화면이 앞이면 올리지 않음)
타자 입력이 풍선/소식 창으로 샘창이 뜰 때 포커스를 가져감WA_ShowWithoutActivating + WS_EX_NOACTIVATE
보조 모니터에서 아이콘 위치가 어긋남바탕화면 아이콘은 물리 픽셀·가상 화면 기준, Qt 는 논리 픽셀dpr 로 나누고 가상 화면 원점을 더함 (배율이 다른 모니터는 안내 메시지)
탐색기가 다시 시작되면 아이콘 차기가 멈춤explorer 안의 ListView 핸들이 바뀜revalidate() 로 연결 되살림
트레이 아이콘이 사라짐탐색기 재시작60초마다 tray.isVisible() 확인 후 show()
알림이 안 옴: 켠 직후/절전 복귀 직후인터넷이 아직 안 붙음 / 시각을 놓침재시도 60·180·600초, 가장 최근 놓친 칸 따라잡기, 설정만 저장해도 안 사라지게
같은 시각 알림이 계속 되풀이실패하면 last_run 이 안 적혀서 다음 점검에 또 실행실행 전에 last_run 저장
보조 프로세스 결과가 한글에서 깨짐파이프의 문자 인코딩(cp949/UTF-8) 불일치json.dumps 기본(ASCII 이스케이프)으로 출력
경비가 PC 를 느리게 함 (CPU 70%)watchdog 이 사건마다 디스크에 '폴더인지' 물음, PowerShell 을 자주 실행ReadDirectoryChangesW 직접 사용, 레지스트리 지문으로 PowerShell 재사용
경비가 자기가 둔 미끼 때문에 오경보다른 실행이 같은 미끼를 새로 덮어씀멀쩡한 기존 미끼는 이어받음(_adopt)
경보 창/풍선의 아이콘이 파이썬 모양작업 표시줄이 프로세스(pythonw.exe) 기준으로 묶음SetCurrentProcessExplicitAppUserModelID("DesktopCat.CatSecretary") + 창/트레이 아이콘 설정
삭제 프로그램이 안 끝남마지막 안내창이 다른 창 뒤에 숨어 클릭을 기다림안내를 별도 프로세스(wscript)로, 항상 맨 앞 플래그
메모리가 100MB 이상 큼Qt 글꼴 엔진, 인터넷 라이브러리QT_QPA_PLATFORM=windows:fontengine=gdi, 인터넷/캘린더는 보조 프로세스
설정 저장 중 꺼지면 파일이 깨짐직접 덮어쓰기임시 파일 → os.replace
